## Порядок выполнения задач

- Выполняй команды чётко и буквально: никакой самодеятельности — не добавляй шаги, анализ, тесты, проверки и правки, о которых не просили.
- Если при выполнении выявлен риск (неоднозначные данные, необратимое действие, расхождение с ожиданием) — сначала задай вопрос, только потом действуй.

## Git — только в неинтерактивном режиме

`git log` / `git diff` / `git show` / `git blame` без флагов уходят в пейджер `less` и «подвисают»: пейджер ждёт ввода, команда не завершается, вывод не читается.

- Всегда добавляй `--no-pager` (то же самое: `-c core.pager=cat` или `GIT_PAGER=cat`).
- Ограничивай вывод: `--oneline`, `-n <N>`, `--stat`, `--no-color`, `--short --branch`.
- Примеры: `git --no-pager status --short --branch`, `git --no-pager log --oneline -n 20`, `git --no-pager diff --stat`, `git --no-pager show --stat HEAD`.
- Длинный вывод сужай фильтрами: `| head -n 50`, `| grep <шаблон>`.
- Никогда не запускай команды, которые ждут ввода: `git log` без флагов, `git rebase -i`, `git add -p`, `git commit` без `-m`, `git commit --amend` без `--no-edit`. Если без них не обойтись — либо сформулируй команду так, чтобы она завершалась сама, либо скажи пользователю выполнить её вручную.
